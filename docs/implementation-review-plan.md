# 전체 구현계획 · 감독관 검토안

상태: 감독관 리뷰 반영 후 사용자가 구현·커밋·푸시·배포까지 재개 승인. 코드 보완과 자동 검증 진행, 실제 ggg 화면 검증은 대기 중이다. 아래 중단 문구는 검토 당시 절차 기록이며 현재 재개 승인이 우선한다.

최종 배포 지시: 사용자는 실제 ggg 검증이 미완료임을 안내받은 뒤 "걍 커밋 푸쉬 배포해"라고 명시했다. 이 지시가 아래 브라우저 검증에 따른 배포 보류 조건보다 우선한다. 미검증 사실을 기록하고 커밋·푸시·배포 및 운영 HTTP 확인을 진행한다.

## 목표와 제한
- 검증된 활성 120종목을 기준으로 한다. 정체 불명·미지원 상품은 추가하지 않는다.
- 검색 중심 홈을 유지하고 큰 대표 제목을 새로 노출하지 않는다.
- 상세 설명 원문과 충분한 설명 분량을 유지한다. 국가/상품 유형과 기존 탐색 카테고리를 구분한다.
- 전체 인기순위와 카테고리 인기순위를 동일한 실제 조회 데이터로 계산한다.
- 캐시는 Redis 사용량을 방어하면서 가격 신선도, 조회수 내구성, 장애 대응을 유지한다.
- 6개 언어, 모바일, 접근성, SEO를 함께 검증한다. 검증 전 커밋·푸시·배포하지 않는다.

## 진행 순서와 작업 범위
1. 현황 확정: 기존 배포와 미커밋 변경을 구분하고 변경 파일별 요구사항을 대조한다. 부분 테스트 통과와 전체 검증 완료를 구분한다.
2. 디자인 확정: 홈의 기존 시각적 위계를 유지한다. 상세는 종목명+고정 액션 영역, 보조 메타, 가격, 순위, 차트, 상품 설명 순으로 구성한다. 작은 화면에서는 보조 정보의 줄바꿈을 허용하고 액션 가림·가로 넘침을 방지한다. 설명은 개요/구조화 사실/원문으로 읽기 쉽게 배치한다. 실제 화면으로 간격과 밀도를 결정한다.
3. 인기순위: 전체와 9개 분류를 제공한다. 모바일 선택기와 데스크톱 필터를 사용한다. 상세에는 전체 및 소속 카테고리 순위와 이동 링크를 둔다. 반도체는 중첩 분류임을 명확히 한다. 조회 기간·갱신 시각·집계 지연·데이터 부족/장애를 구별한다. 분류 변경은 추가 집계 요청 없이 처리한다. 순위 이동은 동일 분류의 이전 스냅샷과 비교한다.
4. 상세 콘텐츠: 공식 출처로 120종목을 대조한다. ADS, ETF, 선물/파생, 일일 레버리지, 상장 전 상품, 환산 단위를 정확히 표시한다. 6개 언어의 사실 요약과 원문을 유지하고 원문 언어를 알린다. 내부 식별자는 숨긴다. 새 API 요청은 만들지 않는다.
5. 공통 UI/기능: 가격 정밀도·부호·비정상 값, 카드 클릭/즐겨찾기 독립 조작, 기존 즐겨찾기 복원/중복 제거, 표 의미구조, 키보드/포커스, 모션 감소를 점검한다. 기존 카테고리·즐겨찾기 URL은 보존한다.
6. 캐시/집계: 기존 가격 캐시와 공유 연결의 회귀를 점검한다. 전체/분류 순위는 같은 조회수 집계와 Redis 잠금·캐시·스냅샷을 재사용한다. 동시 요청, 빈 데이터, Redis 장애, 재시도/중복 처리, 스냅샷 호환성을 검증한다. 호출 수와 저장 필드/응답 크기를 함께 평가한다. 운영 지표 없이 절감률을 단정하지 않는다.
7. SEO: 고유 제목/설명, canonical, 6개 언어 대체 URL, 구조화 데이터, 영구 리디렉션 및 쿼리 보존을 검증한다. 홈 디자인을 해치지 않으면서 페이지 주제와 제목 구조를 점검한다. 필터 URL은 대표 인기순위 URL로 정규화한다. 개인 즐겨찾기는 noindex 처리한다. robots가 렌더링 자원을 막지 않게 한다. 설명 반복·번역 품질·메타 내용과 실제 화면 불일치를 점검한다.
8. 사이트맵 최종 정비: 활성 종목/분류/검색에 적합한 고정 페이지만 포함한다. 미지원/404/리디렉션/개인 페이지/필터 중복은 제외한다. canonical·언어별 URL과 일치하고 lastmod는 실제 수정 근거를 사용한다. XML 유효성 및 모든 URL의 응답을 검사한다. 예상 개수는 실제 라우트 정책을 대조한 후 확정한다.
9. 통합 검증: 의미 있는 단위/Redis 통합 테스트, 타입·린트·프로덕션 빌드, HTTP SEO 검사를 수행한다. ggg(Profile 6)에서 320/360/390px 및 데스크톱, 긴 종목명/다국어, 공유·즐겨찾기·필터/뒤로가기·순위 이동을 검증한다. 브라우저 연결 불가 시 화면 검증 미완료로 보고한다.
10. 배포 단계(계획 재개 후): 감독관 지적 해결 및 필수 검사 통과를 확인한다. ableroyruy 계정/로컬 작성자를 검증하고 커밋·푸시한다. 기존 NightTicker Git 연동으로만 배포한다. 배포 후 상세/인기/가격/robots/sitemap/CDN을 확인한다. 회귀 시 직전 정상 배포로 복구한다.

## 감독 체계와 완료 조건
- 디자인 감독관: 시각적 위계·밀도·여백·순위 배치·기존 홈 일관성 검토.
- UI 감독관: 모바일 동작·반응형·접근성·상태·내비게이션·실제 브라우저 검증 범위 검토.
- SEO 감독관: 인덱싱 정책·중복/언어 URL·콘텐츠·사이트맵·리디렉션 검토.
- 기술 감독관: 데이터 정확성·Redis 비용/장애·호환성·회귀·배포/복구 검토.
- 각 감독관은 차단/중요/권고로 지적하고 계획의 누락과 수용 조건을 제시한다. 구현 담당자의 자체 검증과 구별한다.
- 검토는 읽기 전용이다. 네 검토를 통합하고 해결 방향을 문서화한 뒤 사용자에게 확정안을 보고한다. 사용자 재개 지시 전 구현·커밋·푸시·배포하지 않는다.
- 완료는 코드 존재가 아니라 필수 검증 증거와 미해결 차단 사항 0건으로 판정한다.

## 현재 남은 위험
- 현재 변경은 여러 작업이 합쳐진 미검증 통합 상태다. 일부 개별 검사 통과는 배포 적합성을 보장하지 않는다.
- ggg 브라우저 연결이 확인되지 않아 모바일 실제 화면 검증은 미완료다.
- 운영 Redis 측정 접근이 없어 실제 사용량 절감률은 산출할 수 없다.
- 원문 유지와 다국어 설명 확대로 상세가 길어질 수 있어 실제 밀도 검토가 필요하다.

## 감독관 검토 반영 · 위 본문보다 우선하는 구체 기준

### 디자인
- 기존 배포의 홈/상세/인기 화면을 같은 언어·크기·데이터 상태로 비교한다. 320/390px 및 데스크톱 비교 화면과 변경 이유를 디자인 감독관이 확인한다.
- 홈 검색창 위치·크기, 상단 여백과 첫 화면의 주요 콘텐츠를 보존한다. 큰 제목이나 새 순위 대시보드를 홈에 도입하지 않는다.
- '고정 액션'은 축소되지 않는 액션 묶음을 뜻한다. 문서 흐름 안에 두며 새 sticky/fixed 조작부를 뜻하지 않는다. 긴 이름은 줄바꿈한다. 모바일 좌우 16px 여백을 기준으로 확인한다.
- 시각 우선순위는 종목명 → 현재가·가격 등락 → 인기순위 → 차트 → 설명이다. 보조 메타는 가격보다 약하게 표시한다. 실제 DOM 위치/배치는 비교안에서 확정한다.
- 설명 원문은 접지 않고 유지한다. 개요/사실/원문을 구분하되 동일 언어 동일 문장의 중복을 피하고 원문 언어를 명시한다. 분량 확보를 위해 반복하지 않는다.
- 선택한 순위 범위를 제목에 표시한다. 가격 등락과 순위 변동을 구별하며 반도체는 중첩 분류임을 짧게 설명한다.

### UI
- ggg(Profile 6) 실제 브라우저 검증을 못 하면 UI 승인을 보류하고 커밋·푸시·배포하지 않는다. 현재 연결 문제는 검증 선행조건이다.
- 320px에서 6개 언어의 긴 이름/큰 가격/작은 FX 가격을 확인한다. 360/390px와 데스크톱도 대표 화면을 검증한다. 페이지 가로 넘침, 가격·조작 가림/중첩은 불합격이다. 표 내부 스크롤만 허용하고 모든 열에 키보드·터치로 도달할 수 있어야 한다.
- 전체+9분류의 직접 진입/새로고침/앞뒤 이동/새 탭/언어 전환에서 URL·선택 상태·목록을 유지한다. 분류 전환에 따른 추가 집계·추가 API 요청이 없어야 하며 주기 갱신 요청과 구별해 기록한다.
- 검색 combobox/listbox 상태, 활성 결과 자동 노출, Enter/Escape/Tab, 포커스 복귀, 한글·일본어 IME 입력 중 Enter 오인 방지를 검증한다.
- 가격/차트/순위 각각 로딩·정상·빈 데이터·부분 부족·지연된 마지막 값·실패·복구의 상태표를 만든다. 6개 언어에서 데이터 없음/비교 불가를 0/보합으로 표현하지 않는다. 전날 갱신 시각은 날짜 또는 경과 시간으로 구별한다.
- 메뉴/언어/검색/공유/즐겨찾기의 접근 가능한 이름·상태·포커스를 검증한다. 주요 터치는 44px 목표, 축소 조작은 최소 24px 및 간격을 확보한다. 키보드, VoiceOver, 200% 확대, 대비, 모션 감소를 확인한다.
- 증거표는 요구사항/경로/언어/크기/상태/절차/기대값/실제값/증거/미해결 사항을 포함한다.

### SEO
- 구현 전에 라우트별 index/noindex, canonical, 언어 URL, HTTP 상태, 사이트맵 포함 여부 정책표를 확정한다.
- 인기순위 필터 URL은 선택 쿼리를 유지하며 canonical만 대표 /popular로 지정한다. 필터를 삭제하는 리디렉션은 하지 않는다.
- 사이트맵에는 200 응답·자기 canonical·index 허용 URL만 포함한다. 개인 즐겨찾기는 noindex이며 robots에서 크롤을 막아 noindex 판독을 방해하지 않는다.
- 실제 수정 근거가 없는 lastmod는 생략한다. 모든 URL에 같은 날짜를 일괄 부여하지 않는다. changefreq/priority는 크롤링 보장이 아니며 불필요하면 생략한다.
- 상품별 공식 출처/alias/상태/단위 근거표를 콘텐츠 작성자 외 검토자가 대조한다. 메타·구조화 데이터·화면 내용과 6개 언어 의미가 일치해야 한다.
- 근거표에 출처의 상품별 행·확인일·상장시장·ADS 비율·환산 방식을 포함한다. 출처와 해석이 충돌하면 해당 공개 설명 확정을 보류한다. 현지어 요약과 원문 전체 번역을 구분하고 실제 거래 가능 시간/데이터 지연을 넘는 실시간 보장을 하지 않는다.
- 운영 도메인/프로토콜/영어 기본 경로, 언어별 self-canonical과 상호 hreflang을 대조한다. 대소문자/후행 슬래시//en 정규화의 쿼리·쿠키·Accept-Language·루프를 검사하고 언어 감지 임시 이동과 URL 정규화 영구 이동을 구분한다.
- 미지원 상세/공유 이미지는 실제 404여야 한다. 초기 HTML에서 종목명/개요/단위/출처/내부 링크가 전달되어야 한다. FAQ 데이터는 화면과 일치해야 하며 검색 특수 노출 보장은 완료 기준에서 제외한다.

### 기술
- 같은 고정 데이터로 기존/변경 후 HTTP 요청 수, Redis 명령 수 및 Lua 내부 실행, 키/필드 수, 저장량, 응답 바이트를 비교한다. HTTP 요청 수 불변을 비용 불변으로 표현하지 않는다. Upstash 과금 단위는 공식 기준을 확인한다.
- 원본 288개 버킷 재조회 횟수를 늘리지 않는다. 전체 최대 120필드에 기본 분류 최대 120필드와 반도체 필드가 추가되는 스냅샷 저장 비용을 예산표에 포함한다. 운영 절감률은 측정 전 주장하지 않는다.
- 순위는 5분 버킷 근사·30분 캐시·장애 시 최대 24시간 과거값이라는 현재 한계를 명시한다. 가격은 별도 TTL/최대 stale 정책을 코드와 대조한 뒤 확정한다. 지연/장애를 정상 신선도로 표시하지 않는다.
- 조회수 보존 보장은 서버 승인 배치의 내구성과 멱등성에 한정한다. 최대 10배치 큐, 1시간 초과 이벤트 폐기 등 미승인 이벤트 유실 한계를 명시한다. 동시 요청/타임아웃 재시도/페이지 종료/오프라인/큐 초과/Redis 장애와 복구를 검증한다.
- 기존 v3 서버 캐시, 구/신 브라우저, 시간별 스냅샷 혼재와 배포 직후/시간 경계/롤백 fixture를 검증한다. 분류 이전 순위가 없으면 비교 불가로 표시한다.
- 동률 정렬·분류 내 연속 순위·반도체 중첩·전체 중복 가산 금지를 검사한다. TrendingTicker 등 모든 소비 화면에서 추천을 실제 순위로 오인시키는 경로를 점검한다.
- 즐겨찾기 변환 전 원본을 보존한다. US/반도체 중복, 소문자, 깨진 저장값, 미지원 종목, 저장소 접근 실패에서도 활성 종목/slug를 유지하고 롤백 가능해야 한다.
- 가격 0/1/100 경계, 극소값, 음수/음수 0, NaN/Infinity, 색상/부호 일관성을 검사한다. Next16 proxy/locale 리디렉션/Suspense는 프로덕션 서버에서 검증한다.
- 배포 전 정상 커밋·배포 ID를 기록한다. 배포 후 가격 갱신/조회 기록/전체·분류 순위/즐겨찾기/SEO를 확인하고 실패 시 기록한 정상 배포로 복구한다. 사이트맵 전체 URL 검사에는 동시 요청 제한을 둔다.

## 재개 후 작업 묶음과 승인 순서
1. 정책/비교 화면/비용·상태표 확정 → 감독관 계획 확인.
2. 상세·공통 UI·접근성 → 디자인/UI 검토.
3. 상품 콘텐츠·SEO → 사실 및 SEO 검토.
4. 순위·캐시·데이터 호환 → 기술 검토.
5. 통합 회귀·실제 브라우저 → 4개 감독관 미해결 차단 0건 확인.
6. 사이트맵 최종 생성 및 URL 대조 → SEO 최종 확인.
7. 계정 확인·커밋·푸시·정상 프로젝트 배포·운영 확인.

위 순서는 향후 재개 계획이다. 현재는 계획 문서 작성/검토만 수행하며 구현은 계속 중단한다.

## 추가 승인 범위: 상세 차트 축과 그리드

사용자가 디자인/UI 감독관 검토 후 구현 및 최종 커밋·푸시·배포를 지시했다.

- 상세 variant를 명시하고 오른쪽 가격축, 아래 시간축, 옅은 수평 그리드를 제공한다. 작은 카드의 축은 숨겨 기존 밀도를 유지한다.
- 큰 상세에는 '5분 캔들 · 최근 6시간', 작은 카드에는 '5분 · 6시간'을 6개 언어로 표시한다. 주기/조회 범위는 실제 API와 일치한다.
- 가격축에는 종목별 정확한 단위와 충분한 소수점 정밀도를 사용한다. ADS비율이나 FX를 표시 단계에서 다시 환산하지 않는다. 마지막 캔들 가격은 실시간 현재가와 구별한다.
- Unix timestamp 원본은 바꾸지 않고 브라우저 시간대에서 표시한다. 시간대/UTCoffset, 자정 날짜, 서머타임 중복 시간을 구별한다.
- 글씨는 읽을 수 있는 대비를 확보하고 그리드는 캔들보다 약하게 한다. 320px에서도 가격 라벨을 자르지 않으며 실제 캔들 영역이 읽히도록 한다.
- 확대/이동/십자선은 이번 범위에 포함하지 않는다. API/캐시/Redis/의존성을 추가하지 않는다.
- 코드 리뷰와 시간/가격 회귀 검사를 먼저 수행하고 ggg 실제 화면/동작 검증을 거친다. 실제 검증 전 출시 승인을 대신하지 않는다.
